# 守護：長工作跑完前別讓電腦睡著

來源：https://github.com/realTaki/bot-keepalive （MIT）。

## 為什麼
- 沒有 bot 正在工作時，雲端電腦大約 5 到 7 分鐘就會整台暫停，`nohup`、`tmux` 也一起停，時間會跳，有時限的工作會被誤判逾時。
- 排程（routine）救不了：最短 5 分鐘一次，又常常遲到。
- 有用的做法：bot 在「前景等一個 Shell 指令」時算活躍。所以讓一個小幫手連續做前景等待，直到工作結束。
- 平台 50 分鐘會收掉背景小幫手，所以每段最多等 3 次（約 39 分鐘）就交棒（RELAY），由主對話馬上開下一段。

## 規則：每次開單都要開守護
工作會跑超過 5 分鐘，就一定要做第 1 步和第 3 步。不可以只登記不開小幫手：只登記的話，電腦還是會睡。

## 1. 分離啟動並登記
```bash
mkdir -p ~/.keepalive/jobs ~/.keepalive/ended
cd /path/to/job
setsid nohup bash -c '<指令>; touch DONE' > run.log 2>&1 < /dev/null &
echo "$! $(pwd)" > ~/.keepalive/jobs/<工作名>
```
登記檔內容是 `<PID> <工作資料夾>`。資料夾裡有 `DONE`，或 PID 不在了，就算結束。工作腳本如果已經自己登記（例如流水線開跑時自動寫進 jobs/），就不要重複登記。

## 2. 讓工作不怕暫停
- 逾時用「實際跑了多久」算，不要用牆上時鐘算。
- 定期存檔，斷了也只損失一點點。

## 3. 全電腦只開一個小幫手
- 先看 `~/.keepalive/watcher.lock`。如果它存在、而且 15 分鐘內有更新，表示已經有小幫手在跑：只登記，到這裡就停。
- 否則開一個背景 executor，effort 選 low。告訴它截止時間（寫死確切時刻），而且只能讀、不能改任何東西。然後最多重複 3 次：
  1. 跑一個前景 Shell，`block_until_ms` 設 `760000`：
     ```bash
     alive() { for f in ~/.keepalive/jobs/*; do [ -e "$f" ] || continue; read pid dir < "$f"
       if [ -f "$dir/DONE" ] || ! kill -0 "$pid" 2>/dev/null; then mv "$f" ~/.keepalive/ended/; else echo 1; fi
     done; }
     for i in $(seq 1 144); do touch ~/.keepalive/watcher.lock; [ -z "$(alive)" ] && break; sleep 5; done
     date; ls ~/.keepalive/jobs ~/.keepalive/ended
     ```
  2. 還有工作在跑、還沒過截止時間、也還沒等滿 3 次，就馬上開下一次等待。中間不要寫說明，省額度。
  3. 等滿 3 次就結束，不要刪鎖。只回一行：`RELAY` 加上還在跑的登記檔。
  4. 全部跑完或過了截止時間：刪掉 `watcher.lock`，回報每個工作是完成、消失還是仍在跑，附結束時間和 `run.log` 最後幾行。
- **主對話接棒**：收到 `RELAY` 就立刻用同樣的提示和截止時間開下一段。收到最終回報才算完成。

## 4. 進度另外報
小幫手在結束前不說話。進度由工作自己的通知或另一個排程回報。小幫手在跑的時候，不要再加頻繁的叫醒排程，只會多花錢。

## 5. 遠端工作不用守護
Kaggle、Colab 之類的遠端工作，或等額度重置，不需要電腦醒著。做法：在預計完成時刻排一個一次性 routine，再加一個每小時檢查、完成後自己刪掉的備援 routine。

## 費用
小幫手醒著就會花額度（原作者實測一天約 180 萬 token）。每次交棒也會叫醒主對話一次。只用在真的需要連續跑的工作；超過 2 小時的工作，優先用第 5 節的做法。

## 備註
小幫手卡住或一直重複同一件事，就停掉、重開一個，工作本身不受影響。等平台不再暫停有工作在跑的電腦，就可以拿掉這個做法。
