# bot-keepalive 守護（繁體中文版）

讓雲端電腦在長工作跑完之前不要睡著的小方法。
改寫自 [realTaki/bot-keepalive](https://github.com/realTaki/bot-keepalive)（MIT 授權）。

## 這是什麼？

Grok Bot 用的雲端電腦有個習慣：只要大約 5 到 7 分鐘沒有任何 bot 在做事，整台電腦就會「睡著」（暫停）。
就像手機放著不動會自動鎖螢幕一樣。

問題是，有些工作要跑很久，例如工作單流水線（寫程式、審查、測試一棒接一棒），中途電腦一睡著，工作就跟著停了。

「守護」就是派一個很省力的小幫手，在旁邊一直「等」，讓電腦以為還有人在用，直到工作跑完才放手。

## 有什麼功能？

1. **登記工作**：開工作時，把它記在 `~/.keepalive/jobs/` 這本簿子裡（記下工作編號和資料夾）。
2. **小幫手守著**：小幫手每 5 秒看一次簿子，工作還在跑就繼續等；工作做完（出現 `DONE` 或程式不在了），就把它移到 `ended/`。
3. **全電腦只有一個小幫手**：用 `watcher.lock` 這張「有人值班」的牌子，避免同時開好幾個小幫手浪費額度。
4. **自動交棒**：平台大約 50 分鐘會收掉背景小幫手，所以小幫手每等約 39 分鐘就喊一聲 `RELAY`（交棒），由主對話馬上派下一個接手。
5. **設截止時間**：一定要寫死什麼時候結束，到時間就自己收工，不會無止境花額度。
6. **只讀不改**：小幫手只負責等和看，不碰任何檔案或程式。

## 為了防範什麼？

- **工作做到一半被暫停**：電腦睡著時，`nohup`、`tmux` 這些「背景跑」的方法也一起停，救不了。
- **時間跳掉、被誤判逾時**：電腦醒來時時鐘會突然往前跳，有時限的程式會以為自己超時而自殺（我們遇過 Hermes 因此出現 exit 130）。
- **排程救不了**：排程最短 5 分鐘一次，而且常常遲到，剛好卡在睡著的邊緣。
- **重複開小幫手**：好幾個 bot 各開一個，額度白白多花好幾倍。

## 已經有什麼問題？（老實說）

- **會花額度**：小幫手醒著就在花錢。原作者實測一天大約 180 萬 token。所以只用在真的需要連續跑的工作，超過 2 小時的工作建議改用別的方法（例如遠端跑、排一次性提醒）。
- **交棒會吵醒主對話**：每約 39 分鐘交棒一次，主對話就要醒來一次。
- **主對話忘了接棒就會斷**：收到 `RELAY` 沒有馬上派下一個，電腦就會睡著。
- **只登記不開小幫手 = 沒用**：我們實際犯過這個錯：工作有登記，但沒開小幫手，電腦照樣睡著。所以現在規定「每次開單都一定要開守護」。
- **小幫手可能卡住**：如果它一直重複同一件事，就停掉重開一個，工作本身不受影響。
- **只是權宜之計**：這是繞過平台的暫停習慣。等平台不再暫停有工作在跑的電腦，這個方法就可以拿掉。
- **遠端工作不需要**：Kaggle、Colab 這類在別台電腦跑的工作，或只是在等額度重置，不用開守護。

## 怎麼用？

完整步驟在 [skills/bot-keepalive/SKILL.md](skills/bot-keepalive/SKILL.md)。簡單說：

1. 用 `setsid nohup` 把工作放到背景跑，並登記到 `~/.keepalive/jobs/`。
2. 確認沒有別的小幫手在值班（看 `watcher.lock`）。
3. 開一個低耗費的小幫手，告訴它截止時間，讓它開始守。
4. 收到 `RELAY` 就立刻再開下一個，收到最終回報才算結束。
